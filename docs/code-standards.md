# Code Standards

Conventions actually used in this repo. Copy existing patterns before inventing new ones.

## Layout rules
- Two Go modules, not one workspace: `api/` (`module danh-birthday/api`) and `tools/fetch-assets/` (`module danh-birthday/fetch-assets`). Run `go` commands inside each module directory.
- Frontend is `site/` only. Nothing under `site/` may use a build step, bundler, or npm package.
- Keep the file-size guideline: ~200 LOC for code. Known exception: `api/server_test.go` (393 LOC).

## Frontend (`site/`)

### Modules
- Vanilla ES modules loaded with `<script type="module">` (`site/index.html` → `js/main.js`).
- Import with relative paths and include the `.js` extension: `import { playSfx } from '../audio-8bit.js'`.
- Lazy modules (games, guestbook) use `import()` in `main.js` and must export `mount(el)`.
- Shared state with the outside world goes through named exports or `window` CustomEvents (`egg:gameover`). Don't add globals.

### Paths
- All URLs are relative (`assets/img/...`, `js/...`). The site is served under `/happy-birthday-danh/`. A leading `/` breaks it.
- `API_BASE` in `site/js/config.js` is the only absolute URL in the frontend. Empty string means offline. No trailing slash.

### Rendering and user data
- User-supplied text (names, wishes, scores) goes through `textContent` only.
- `innerHTML` is allowed only for static template strings with no user data. Existing code marks them with `// static markup only`. Keep that comment.
- Don't use `eval`, `new Function`, or inline event attributes.

### Names
- JS and CSS files: kebab-case (`api-client.js`, `steal-an-egg.js`, `guestbook.css`).
- Exports: `mount` for section entry points, verb names for helpers (`runLoader`, `playSfx`, `renderWearing`).
- localStorage keys: `bd-` prefix (`bd-muted`, `bd-name`, `bd-best`, `bd-fruits`).
- Data files in `site/assets/data/` (kebab-case JSON), generated by `tools/fetch-assets`.

### CSS
- Design tokens in `site/css/tokens.css` (`--bg`, `--space-*`, `--ease-*`). Use tokens, not raw values, for colors and spacing.
- One file per section: `base`, `sections`, `games`, `guestbook`.
- Touch targets ≥ 44px. Honor `prefers-reduced-motion` (see `base.css`).
- Fonts: Bungee and Chakra Petch only (Russo One lacks Vietnamese glyphs).

### Accessibility
- Modal-like overlays set `inert` on the content behind (see `loader.js`).
- Live status uses `aria-live`. Icons are inline SVG or emoji with `aria-hidden` or labels.

## API (`api/`)

### Files
- Go files are snake_case: `wish_handler.go`, `store_turso.go`, `client_ip_test.go`.
- One concern per file. Handlers live in `*_handler.go`. Persistence implements the `Store` interface (`store.go`).
- Entry: `main.go` (`run`, `newStore`). Wiring and middleware: `server.go` (`newServer`). Config: `config.go` (`loadConfig`).

### Handlers
- Decode with `bindJSON(c, &req)`. It enforces `application/json`.
- Validate with `validateName` / `validateMessage` / `validateScore` (`validate.go`) and return `badRequest(err)`.
- Return `errInternal` for store failures. Log the detail with `c.Logger()`, not in the response.
- Use pointer fields for required numbers (`Score *int`) so a missing value is rejected, not stored as 0.
- Every response error becomes `{"error": "..."}` through `jsonErrorHandler`. Don't write raw `Error` text to clients.

### Persistence
- New storage calls must use a context with timeout (`storeTimeout`, 5 s) in `store_turso.go`.
- Timestamps: UTC, millisecond, fixed-width layout (`dbTimeLayout`). Keep it, or sort order breaks.
- Schema changes are additive `CREATE ... IF NOT EXISTS` in the `schema` constant. No migration tool exists.

### Config
- Read env with `envOr(key, default)` or `os.Getenv`. Add new vars in `loadConfig` and document them in [deployment-guide](./deployment-guide.md).
- Secrets come from the Render dashboard (`sync: false` in `render.yaml`). Never commit them.

### Tests
- Go tests sit next to code (`*_test.go`). Run `go test -race ./...` inside `api/`.
- Use the memory store and injected `Config` (see `newServer(store, cfg)`) so tests are deterministic.

## Asset tool (`tools/fetch-assets/`)
- Files are snake_case (`image_optimize.go`, `roblox_api.go`).
- Keep the run idempotent: skip existing outputs unless `-force`.
- Downloads go through `download(url, dest, force)`. Don't hotlink Roblox CDN URLs from the site.

## Commits and docs
- Conventional commits: `feat`, `fix`, `refactor`, `test`, `style`, `perf`, `ci`, `build`.
- No AI attribution in commits, PRs, or doc files.
- Docs live in `docs/`. `plans/` and `.claude/` are gitignored local tooling.
